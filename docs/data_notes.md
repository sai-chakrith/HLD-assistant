## Parser design implications

(Hand-written from the generated evidence above plus direct reading of the PDFs. Preserved by scripts/inspect_pdfs.py on regeneration.)

### 0. Headline finding: the real PDFs have almost NO machine-readable port/interface tables

All five documents are *explanation* documents (prose + diagrams). The detailed port/interface lists live in an external "MasterTable" that is NOT in the PDFs (BodyComfort 4.3.12 and Chassis 2.2.3 / 5.2.1 reference it). Consequences:
- There are NO tables with columns like Port | Interface | Direction. Table-based extraction of ports/interfaces/signals from the real docs yields ~0 entities. This is expected, not a parser bug.
- Tables carrying useful structure: page-1 metadata, the change-history table, the naming-convention example table, seat/axis lookup tables (BodyComfort 4.4), Chassis feature matrices, HMI interface description tables (2-column).
- pdfplumber `find_tables()` reports many FALSE tables on diagram pages (BodyComfort p8, 11, 13, 15, 16, 17, 29, 30; Chassis p9, 15, 19; R3.2.3 shifted by one page). Their cells are garbled diagram labels (`'AutoWimpingEvaluator::AutoWipingEvaluato...'`, `'[seat] man-adj panel'`, reversed text `'noitisopmoC ydoB .celE'`, doubled chars `'FFeeaattuurreess'`). Filter: require a recognised header row (section 4) OR a 2-column key/value layout; drop single-column tables and tables whose cells contain `[`, `::`, or more than ~300 chars.
- Entity extraction for real docs must be heuristic (headings + prose sentences + port-label strings from diagrams). The synthetic HLD (checkpoint 4) is where table extraction is really exercised; give its tables the header style in section 4.

## Extraction uplift (Phase C)

Three new layers on top of the table + heading/regex extraction. Every entity now carries `extraction_method` (table | diagram | heuristic | llm | convention), `confidence` (High | Medium | Low) and, per source, `method` + the exact page (LLM sources also carry the evidence quote). Merge precedence is table > diagram > heuristic > llm > convention; lower-ranked sources only fill empty/unknown fields, but all sources are kept (best evidence first, so `page`/`section` of an entity point at its best source).

Confidence rules: table = High; diagram signal = High when the label sits <= 7 pt from its arrow and both arrow ends touch a titled box within 3 pt (else Medium); diagram port = High when the label is <= 3 pt from the box border; diagram component = High when it owns at least one such port; heuristic = Medium; llm = Medium; convention = Low/Medium (never High). When two independent methods (not counting convention) agree on the same entity the merged confidence goes up one step.

### C1 Diagram geometry (`app/diagram.py`, method="diagram")
- The real diagrams are vector graphics. Boxes = stroked rectangles or dashed outlines (a drawing with >= 8 dash items whose bbox is >= 22 pt), duplicates and stacked instance boxes are aliased to the titled front box, directly adjacent untitled boxes alias to their titled neighbour. Arrows = chains of line segments joined at their ends (T-junctions included) that end in a filled triangle; the triangle apex (not the line end) is where the arrow lands. Port markers = small stroked squares.
- Text (`get_text("dict")` lines): rotated lines and bold/larger-than-label lines inside a box are its title (rotated fragments such as `Cen`+`tral` are re-joined, instance qualifiers `[mirror]`, `SW-C` captions and italic annotations are dropped, overprinted duplicates are collapsed, doubled text `FFeeaattuurree` is collapsed). A label of label-size close to a box border (<= 20 pt) is a port of that box; labels just outside a border (<= 16 pt) count only if a port marker or arrow end sits there. `Name / kind` labels are assigned to the nearest horizontal arrow segment (<= 9 pt); the signal sender is the box at the tail nearest to the label, receivers are all boxes at arrow heads. Port direction = provided when an arrow leaves the box at the port's height, required when one arrives.
- A page is only treated as an interface diagram when it has >= 2 signal labels or >= 3 port markers, so conceptual block diagrams (Chassis pages 8, 14, 16) produce nothing instead of noise.
- All thresholds live in `settings` (`DIAG_*` env vars: min box 22, join tol 1.5, touch tol 4, high dist 3, label-arrow 9, high label dist 7, port inside margin 20, port asym 8, port outside dist 16, port arrow y 6).
- Section/page of a diagram entity = the page where it is drawn; the section is the one containing that page, ignoring headings printed below the figure (this fixes the old "section start page" bug: `StaMirrorFault` is now p12, not p10; heuristic sources of a signal that also has a diagram source are dropped).
- `scripts/debug_diagram.py <doc_id> <page> [out.png]` draws boxes (blue, `#idx title`), port labels (green = inside, orange = outside, `->#box P/R/?` = box and direction), signal labels (red, `#sender->#receivers`) and arrows (magenta, o = tail, x = head). Reviewed PNGs are in `docs/diagram_checks/` (bodycomfort_r3.2.3 pages 10, 12, 14, 15, 16).

### C2 Naming convention (`infer_by_convention`, method="convention")
Signal prefixes give `sender_role`/`receiver_role` (Cmd master->actuator, Req sensor->master, Err actuator->master are Medium; Sta, Dis, Hmi are Low). A port whose direction is still `unknown` gets provided/required when `<Prefix><PortName>` matches a signal whose sender/receivers are known. Convention ranks last in the merge and can never override anything. Deliberately NOT done: inventing ports from signal names (first prototype did; real port names such as `Activation` differ from `<signal minus prefix>`, so those were wrong).

### C3 LLM prose extraction (`extract_from_prose`, method="llm")
qwen2.5:3b through the cached Ollama provider, one section (chunk of <= 3000 chars, so prompt + output stay inside num_ctx 4096) per call, pydantic schema (components, ports, interfaces, signals, each with an evidence quote <= 25 words). Skipped: front matter/TOC/legal sections, sections with < 250 chars of prose after removing figure-label lines and page headers. Anti-hallucination: an entity is dropped unless its quote occurs verbatim (case/whitespace-insensitive, hyphenation rejoined) in the section text, its name occurs in the section text, and the name looks like an identifier (no generic words, no `SW-C` captions, no repeated tokens, no `[instance]`).
